# DevPath 구현 상태

DevPath의 구현 상태와 검증 결과를 기록하는 **유일한 상태 문서**다. 다른 문서와 에이전트 가이드는 상태·버전·테스트 수를
따로 적지 않고 이 문서를 가리킨다. 요구사항은 [docs/SRS.md](SRS.md), 기술 결정은 [docs/ADR.md](ADR.md), 테스트 방식은
[docs/TEST_PLAN.md](TEST_PLAN.md)를 본다. 로컬 실행 문제는 [docs/RUNBOOK.md](RUNBOOK.md)를 본다. 이 문서는 마일스톤 완료를
선언하거나 소유자 승인을 대신하지 않는다.

## 5. MVP 게이트 기록 요약

M34 근거는 2026-09-28에 정리했다. 소유자 승인은 아직 없다.

| 기준 | 결과 | 남은 확인 |
|---|---|---|
| 로그인, 목표 직무 선택, 저장소 등록·보관 | PASS | 소유자 검토 |
| GitHub 안전 연결 | PARTIAL | 실제 provider 권한·토큰 폐기 점검 |
| 비동기 동기화, 불변 snapshot, 새로고침 후 추적 | PASS | 소유자 검토 |
| 특징 추출, 버전 있는 Rule Engine 결과, Skill Matrix | PASS | golden fixture 범위 검토 |
| 준비도·Skill Gap, 추천, 분석·Matrix 비교, 기술별 이력·근거 | PASS | 소유자 검토 |
| 화면 결과 표시, 권한 적용 | PASS | 수동 보조기술 점검, 외부 보안 검토 |
| 핵심 telemetry | PARTIAL | ADR-031 |
| 핵심 테스트 통과 | PASS | 호스팅 CI 없음 |
| 배포 smoke | PARTIAL | ADR-033·034, 스테이징 |

실제 provider 점검 기록:

- 2026-08-25 로컬: GitHub OAuth 로그인 → 저장소 탐색 → 동기화(약 4초) → snapshot → 결정론 분석 → 대시보드·로드맵까지 통과.
  JDBC 세션이 백엔드 재시작 2회 후에도 유지됐고, 로그아웃(204)과 절대 만료(401)가 감사 기록을 남겼다.
- 2026-09-07·09 로컬 Ollama: `qwen2.5:3b`로 기술 설명·학습 안내 응답이 검증을 통과했다. `qwen2.5:7b`로 저장소 리뷰
  산출물을 생성·검증·저장하고 분석 화면에 표시했다.
- 승인 기록: 엔지니어링 자체 검토 PENDING, 보안 검토 PENDING, 접근성 수동 점검 PARTIAL, 배포 검토 BLOCKED, 실제 provider 시연 PASS, MVP 승인 PENDING.

알려진 제한: Spring Session JDBC는 유휴 만료 시 이벤트를 내지 않아 유휴 만료 감사 기록이 없다. Notion 수집·검색과 AI
기능은 실제 provider 점검과 승인이 남아 있다.

## 6. 남은 과제

- M34 MVP 게이트와 M35–M43 지식·AI 기능의 소유자 승인, 실제 provider 점검.
- 운영 오브젝트 스토리지, 배포·secret, 시연 환경 결정(ADR-029·031·033·034).
- snapshot 목록과 이력 endpoint에 페이지 크기 제한이 없다(계약 결정 필요).
- 대시보드 목표 기준선·단계 타일, 저장소 목록의 주 기술 표시는 API 변경이 필요하다.
- 비로그인 deep link가 인증 레이아웃을 그리고, router가 모듈 import 시점에 생성된다.
- 확인창(`ConfirmDialog`) 뒤 배경이 inert 처리되지 않는다.
- 보관된 저장소의 분석 불가 안내 문구가 백엔드 동작과 다르고, 분석 버튼이 설명 없이 비활성화된다.
- 저장된 생성 작업 조회가 404여도 저장된 작업 정보가 지워지지 않는다.
- 근거 상태: 이력 항목 `NONE`/`INSUFFICIENT` 단위 테스트 없음, 과거 Matrix에도 재분석 안내 표시, 중복 `aria-label`.
- 일부 텍스트 링크 높이(24–26px)가 [DESIGN.md](../DESIGN.md) 44px 지침에 못 미친다. 다시 시도·돌아가기 라벨이 일반적이다.
- 규칙 결과 링크가 모두 한 섹션 anchor를 가리키고, AI 패널 5개가 같은 prop 연결을 반복한다.
- 포커스 링·색상 style guard가 같은 specificity 규칙과 일부 색상 표기를 검사하지 못한다.
- Hibernate `order_inserts`가 향후 부모·자식 혼합 flush 순서를 바꿀 수 있다(외래 키가 일반 UUID 컬럼).
- 수동 스크린 리더 점검을 하지 않았다.
